# Участие в разработке

## Правила проекта

- Проект работает только с файлами `.ewb`; EWB не устанавливается, не
  запускается и не автоматизируется.
- Код должен оставаться clean-room: не добавляйте исполняемые файлы EWB, её
  библиотеки, ресурсы, шрифты и файлы, созданные приложением, в git.
- Каталог `local/` полностью игнорируется git. В нём могут лежать локальные
  бинарники, база IDA и личные схемы; в коммиты они не попадают.
- Изменения формата должны сохранять побайтовый round-trip документа. Сервер
  отказывается редактировать файл, для которого это условие не выполняется.
- Внешние Python-зависимости не используются. Минимальная версия — Python 3.8.

## Тесты

Из корня репозитория:

```bash
python3 -m unittest discover -s tests -v
```

Тесты создают временные файлы, не трогают `local/` и пропускают проверку
исходной схемы, если её нет. CI запускает тот же набор на нескольких версиях
Python.

## Стиль

- Отступы — 4 пробела, окончания строк — LF (см. `.editorconfig`).
- Комментарии и docstring — по-английски, пользовательская документация — по-русски.
- Новые инструменты MCP должны иметь описание, JSON-схему аргументов и
  аннотации `readOnlyHint` / `destructiveHint`, если это применимо.
- Ошибки инструмента возвращаются как `ToolError` с понятным текстом; сервер
  не должен писать трассировку в stdout.
- При добавлении клиента обновите его манифест, раздел в `docs/INSTALL.md` и
  `ManifestTests` в `tests/test_ewb_mcp.py`. Имя и версия плагина должны
  совпадать с корневым `plugin.json`.
- При изменении `PARTS` или `PINS` в `scripts/ewb_parts.py` обновите таблицу в
  `docs/CATALOG.md`: тест `test_catalog_document_covers_every_part` проверяет,
  что описаны все записи каталога.
