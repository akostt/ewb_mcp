# Инструменты MCP

Сервер `scripts/server.py` предоставляет 11 инструментов с префиксом `ewb_`. Имена
инструментов в конкретном клиенте могут иметь префикс сервера, например
`mcp__ewb512__ewb_read_schematic`.

## Общие правила

- Путь `path` должен указывать на файл `.ewb` и находиться в разрешённом
  каталоге.
- Индексы элементов и проводов нулевые.
- Позиции и длины — целые числа в координатах схемы EWB.
- Поворот `rotation` — целое от 0 до 7.
- Значения `value` можно передавать числом или строкой с суффиксом:
  `p` = 1e-12, `n` = 1e-9, `u`/`µ` = 1e-6, `m` = 1e-3, `k`/`K` = 1e3,
  `meg` = 1e6, `M` = 1e6, `g`/`G` = 1e9. Регистр важен: `m` — милли,
  `M` — мега.
- Компоненты адресуются либо `index`, либо `ref` (RefID). Для земли RefID
  всегда `"0"`, поэтому при нескольких землях используйте `index`.
- Все операции редактирования сначала проверяют документ и только потом
  записывают файл. Старый файл сохраняется рядом как `<имя>.ewb.bak`.
- Запись атомарная: временный файл в том же каталоге, затем `os.replace`.
- Если парсер не воспроизводит исходный документ байт-в-байт, редактирование
  запрещается. Это защищает незнакомые варианты формата от повреждения.

## ewb_list_parts

Возвращает каталог компонентов EWB 5.12: PartNum, имя, префикс обозначения,
описание, значения по умолчанию, число выводов, известные повороты и смещения
выводов. Полный список всех 40 записей с пояснениями — в
[`CATALOG.md`](CATALOG.md).

Аргументы:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `query` | string | `""` | Подстрока для поиска по номеру, имени, префиксу и описанию. |
| `only_with_pins` | boolean | `false` | Только детали с известной геометрией выводов. |
| `include_rotations` | boolean | `true` | Включать карту `rotations`. |

Пример:

```json
{"query": "resistor"}
```

Ответ:

```json
{
  "count": 1,
  "parts": [
    {
      "partnum": 1,
      "name": "RESISTOR",
      "ref_prefix": "R",
      "description": "Resistor",
      "value_count": 5,
      "value_default": [1, 0, 0, 0, 0],
      "model_units_count": 5,
      "model_units_default": [1, 0, 0, 0, 0],
      "model_default": "",
      "rotations": {
        "0": {"0": [-20, -10], "1": [40, -10]},
        "1": {"0": [-10, -20], "1": [-10, 40]},
        "4": {"0": [-20, -10], "1": [40, -10]},
        "5": {"0": [-10, 40], "1": [-10, -20]},
        "7": {"0": [-10, 40], "1": [-10, -20]}
      },
      "default_rotation": 0,
      "terminal_count": 2
    }
  ]
}
```

`rotations` — смещения выводов относительно `Position`. Если для нужного
поворота геометрии нет, компонент всё равно можно создать, но провод к нему
будет сохранён без явного маршрута `segs`.

## ewb_read_schematic

Читает `.ewb`, декодирует контейнер и документ, возвращает компоненты, провода,
цепи и диагностику.

Аргументы:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `path` | string | обязателен | Путь к `.ewb`. |
| `include_pins` | boolean | `true` | Добавлять абсолютные координаты выводов. |
| `include_wires` | boolean | `true` | Добавлять провода. |
| `include_nets` | boolean | `true` | Добавлять цепи. |
| `include_text` | boolean | `false` | Вернуть декодированный текст `Project_5_1`. |

Элемент ответа:

```json
{
  "index": 3,
  "kind": "Comp",
  "partnum": 1,
  "name": "RESISTOR",
  "refid": "R1",
  "position": {"x": 500, "y": 460, "rotation": 1},
  "value": [1000, 0, 0, 0, 0],
  "model_units": [1, 0, 0, 0, 0],
  "model": "",
  "label": null,
  "pins": {"0": [490, 440], "1": [490, 500]},
  "pin_geometry_known": true
}
```

Провод:

```json
{
  "index": 0,
  "from": {"index": 2, "refid": "V1", "pin": 1},
  "to": {"index": 3, "refid": "R1", "pin": 0},
  "node": "0",
  "colour": 0,
  "has_route": true,
  "segs": [[1, 70], [8, 20]]
}
```

Цепь:

```json
{
  "net": 1,
  "node_labels": ["0"],
  "pins": [{"refid": "V1", "pin": 0}, {"refid": "R1", "pin": 0}]
}
```

`nets` строятся по связности проводов, а не по `node_p`. Поле `node_p`
используется только как метка и попадает в `node_labels`.

Ответ также содержит:

- `format.header` — разобранный заголовок контейнера;
- `format.document_roundtrip_exact` — совпал ли текст после разбора;
- `counts` — число элементов, проводов и цепей;
- `errors` и `warnings` — результат структурной проверки.

## ewb_render_svg

Строит SVG-превью схемы. Не изменяет `.ewb`.

Аргументы:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `path` | string | обязателен | Исходная схема. |
| `output_path` | string | `<имя>.svg` рядом | Куда записать SVG. |
| `width` | integer | `1400` | Ширина, 200..20000. |
| `height` | integer | `900` | Высота, 200..20000. |
| `inline` | boolean | `false` | Вернуть SVG-разметку в ответе. |

Ответ:

```json
{
  "path": "/path/to/preview.svg",
  "bytes": 15234,
  "width": 1400,
  "height": 900,
  "element_count": 6,
  "wire_count": 5
}
```

SVG — приблизительная визуализация для проверки расположения и связей, а не
попиксельная копия редактора EWB. Он не заменяет открытие файла в EWB.

## ewb_create_schematic

Создаёт новый `.ewb` из минимального синтетического документа `Project_5_1`
и, при необходимости, сразу добавляет компоненты и провода.

Аргументы:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `path` | string | обязателен | Путь нового файла, оканчивается на `.ewb`. |
| `overwrite` | boolean | `false` | Разрешить замену существующего файла. |
| `description` | string | `""` | Описание в заголовке контейнера. |
| `components` | array | `[]` | Список компонентов. |
| `wires` | array | `[]` | Список проводов. |

Компонент:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `part` | string или integer | да | Имя или PartNum, например `"RESISTOR"` или `1`. |
| `x`, `y` | integer | да | Позиция. |
| `ref` | string или integer | нет | RefID; если не указан, генерируется. |
| `rotation` | integer | нет | 0..7; по умолчанию — типовой для детали. |
| `value` | number, string или array | нет | Значение; недостающие элементы берутся по умолчанию. |
| `model` | string | нет | `ModelName`, если у детали есть это поле. |

Провод:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `from`, `to` | string или integer | да | RefID или индекс компонента **в этом же вызове**. |
| `from_pin`, `to_pin` | integer | да | Номер вывода, начиная с 0. |
| `route` | `"auto"`, `"none"` или массив | нет | Маршрут; по умолчанию `"auto"`. |
| `node` | string | нет | Метка `node_p`, по умолчанию `"0"`. |
| `colour` | integer | нет | Цвет провода, по умолчанию 0. |
| `wire_id` | integer | нет | Идентификатор провода, по умолчанию 0. |
| `allow_duplicate` | boolean | нет | Разрешить второй провод между теми же выводами. |

Пример:

```json
{
  "path": "/tmp/rc_led.ewb",
  "description": "RC + LED",
  "components": [
    {"part": "GROUND", "x": 400, "y": 620},
    {"part": "GROUND", "x": 730, "y": 620},
    {"part": "BATTERY", "ref": "V1", "x": 400, "y": 500, "value": 9},
    {"part": "RESISTOR", "ref": "R1", "x": 500, "y": 460, "rotation": 1, "value": "1k"},
    {"part": "CAPACITOR", "ref": "C1", "x": 600, "y": 480, "value": "1u"},
    {"part": "LED", "ref": "D1", "x": 700, "y": 480, "rotation": 2}
  ],
  "wires": [
    {"from": "V1", "from_pin": 1, "to": "R1", "to_pin": 0},
    {"from": "R1", "from_pin": 1, "to": "C1", "to_pin": 0},
    {"from": "C1", "from_pin": 1, "to": "D1", "to_pin": 1},
    {"from": "D1", "from_pin": 0, "to": 1, "to_pin": 0},
    {"from": "V1", "from_pin": 0, "to": 0, "to_pin": 0}
  ]
}
```

Здесь `"to": 1` — индекс второй земли в списке компонентов, а не RefID.

Ответ содержит `path`, `created`, `description`, `element_count`,
`wire_count`, `net_count`, `elements`, `wires`, `warnings` и `errors`.
При любой ошибке создания файл не записывается.

## ewb_add_component

Добавляет один компонент в существующую схему.

Аргументы:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `path` | string | да | Схема. |
| `part` | string или integer | да | Имя или PartNum. |
| `x`, `y` | integer | да | Позиция. |
| `ref` | string или integer | нет | RefID. |
| `rotation` | integer | нет | 0..7. |
| `value` | number, string или array | нет | Значение. |
| `model` | string | нет | `ModelName`. |

Ответ: `path`, `bytes`, `element` (полное описание нового элемента),
`element_count`, `wire_count`, `warnings`.

Если у детали нет поля `Value` или `ModelName`, передача соответствующего
аргумента возвращает ошибку.

## ewb_add_wire

Соединяет два вывода проводом.

Аргументы:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `path` | string | да | Схема. |
| `from`, `to` | string или integer | да | RefID или индекс элемента. |
| `from_pin`, `to_pin` | integer | да | Номер вывода. |
| `route` | `"auto"`, `"none"` или массив | нет | Маршрут. |
| `node` | string | нет | Метка цепи. |
| `colour` | integer | нет | Цвет. |
| `wire_id` | integer | нет | Идентификатор. |
| `allow_duplicate` | boolean | нет | Разрешить дубликат. |

Ответ: `path`, `bytes`, `wire`, `element_count`, `wire_count`, `warnings`.

Проверки:

- нельзя соединить вывод сам с собой;
- номер вывода должен существовать;
- дубликат соединения запрещён, если `allow_duplicate=false`;
- явный маршрут должен заканчиваться в координате целевого вывода.

## ewb_update_component

Перемещает, поворачивает, переименовывает компонент или меняет его значение и
модель. Провода, касающиеся компонента, пересчитываются.

Аргументы:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `path` | string | да | Схема. |
| `index` или `ref` | integer или string | да | Селектор компонента. |
| `x`, `y` | integer | нет | Новая позиция. |
| `rotation` | integer | нет | Новый поворот 0..7. |
| `refid` | string или integer | нет | Новый RefID. |
| `value` | number, string или array | нет | Новое значение. |
| `model` | string | нет | Новое `ModelName`. |

Ответ: `path`, `bytes`, `element`, `changes`, `warnings`.

В `changes` может быть `position`, `refid`, `value`, `model` и
`rerouted_wires` — список проводов с флагом `routed`.

Если для нового положения или поворота геометрия выводов неизвестна, маршрут
провода удаляется, чтобы EWB построил его сам; в `warnings` появляется
предупреждение.

## ewb_update_wire

Меняет маршрут, метку, цвет или идентификатор провода.

Аргументы:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `path` | string | да | Схема. |
| `index` | integer | да | Индекс провода. |
| `route` | `"auto"`, `"none"` или массив | нет | Новый маршрут. |
| `node` | string | нет | Новая метка. |
| `colour` | integer | нет | Новый цвет. |
| `wire_id` | integer | нет | Новый идентификатор. |

`"auto"` пересчитывает ортогональный маршрут по текущим координатам выводов.
`"none"` удаляет `segs`, оставляя маршрутизацию EWB.

Ответ: `path`, `bytes`, `wire`, `changes`, `warnings`.

## ewb_remove_component

Удаляет компонент и, по умолчанию, все подключённые к нему провода. Индексы
элементов в оставшихся проводах пересчитываются.

Аргументы:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `path` | string | обязателен | Схема. |
| `index` или `ref` | integer или string | обязателен | Селектор компонента. |
| `remove_wires` | boolean | `true` | Удалить подключённые провода. |

Если `remove_wires=false` и провода подключены, операция завершается ошибкой.

Ответ: `path`, `bytes`, `removed_element`, `removed_wires`, `element_count`,
`wire_count`, `warnings`.

## ewb_remove_wire

Удаляет один провод по индексу.

Аргументы: `path`, `index`.

Ответ: `path`, `bytes`, `removed_wire`, `element_count`, `wire_count`,
`warnings`.

## ewb_validate

Проверяет контейнер, документ, элементы, провода, выводы, маршруты и
контрольную сумму. Ничего не изменяет.

Аргумент: `path`.

Ответ:

```json
{
  "valid": true,
  "path": "/path/to/circuit.ewb",
  "format": {
    "header": {
      "product": "Electronics Workbench Circuit File",
      "version": "5",
      "charset": "ANSI",
      "description": "RC + LED",
      "encryption_type": 2,
      "vector_graphics": 0
    },
    "document_bytes": 3120,
    "payload_blocks": 4
  },
  "errors": [],
  "warnings": [],
  "checks": {
    "document_roundtrip_exact": true,
    "container_roundtrip_exact": true,
    "checksum_matches": true
  },
  "details": {
    "unknown_parts": [],
    "missing_pin_geometry": [],
    "pin_mismatches": [],
    "duplicate_refids": {},
    "ground_count": 2
  },
  "counts": {"elements": 6, "wires": 5, "nets": 5}
}
```

`valid` равен `false`, если файл не открывается, не является `.ewb`, имеет
повреждённый контейнер или структурные ошибки. Предупреждения не делают файл
невалидным.

Если файл не удалось прочитать, инструмент не выбрасывает исключение, а
возвращает `valid: false` и текст ошибки в `errors`. Так удобнее
диагностировать путь и повреждённые файлы.

## Коды направлений маршрута

`route` — массив пар `[direction, length]`:

| Код | Направление |
|---|---|
| 1 | +x (вправо) |
| 2 | +y (вниз, как в координатах EWB) |
| 4 | -x (влево) |
| 8 | -y (вверх) |
| 3 | +x +y (диагональ) |
| 6 | -x +y |
| 9 | +x -y |
| 12 | -x -y |

Пример явного маршрута:

```json
{"route": [[1, 70], [2, 20], [4, 30]]}
```

Длина должна быть положительной. Маршрут проверяется по конечной точке
целевого вывода.

## Типовые ошибки

| Сообщение | Причина | Что делать |
|---|---|---|
| `path ... is outside the allowed directories` | Путь вне разрешённых корней. | Задайте `EWB_MCP_ALLOWED_DIRS` или положите схему в проект. |
| `expected a .ewb file` | Другое расширение. | Используйте `.ewb`. |
| `file not found` | Нет файла. | Проверьте путь. |
| `refusing to edit ... byte-for-byte` | Незнакомый вариант документа. | Файл можно читать, но не редактировать; сообщите о нём. |
| `reference '0' is ambiguous` | Несколько земель. | Используйте `index`. |
| `pin geometry is unknown` | Нет данных для поворота. | Провода будут без `segs`; EWB построит маршрут сам. |
| `explicit route does not end at the target pin` | Неверный маршрут. | Используйте `"auto"` или пересчитайте сегменты. |
| `part ... has no Value field` | У детали нет `Value`. | Уберите `value`. |
| `component.ref must not be empty` | Пустой RefID. | Укажите непустое имя или не передавайте `ref`. |
