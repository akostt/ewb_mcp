# Каталог компонентов EWB 5.12

Сервер поддерживает все 40 записей библиотеки EWB 5.12 — `PartNum` от 0 до
39. Имена, префиксы обозначений и описания восстановлены из таблицы частей
`COMPDAT.DLL` (`sub_410293`); те же данные возвращает инструмент
[`ewb_list_parts`](TOOLS.md#ewb_list_parts).

Полный машинный каталог с точными смещениями выводов доступен в любой момент:

```json
{"query": "", "only_with_pins": false, "include_rotations": true}
```

## Как добавить компонент

В `ewb_add_component` и в массиве `components` инструмента
`ewb_create_schematic` используются одни и те же поля:

```json
{
  "part": "RESISTOR",
  "ref": "R1",
  "x": 500,
  "y": 460,
  "rotation": 1,
  "value": "1k"
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `part` | да | Имя из таблицы ниже или число `PartNum` 0..39. Регистр не важен, пробелы можно заменять подчёркиваниями. |
| `x`, `y` | да | Координаты точки привязки компонента в системе координат EWB. |
| `rotation` | нет | Код поворота 0..7. По умолчанию берётся наблюдаемое рабочее положение детали. |
| `ref` | нет | Обозначение, например `R1`. Если не задано, сервер подбирает следующее свободное. |
| `value` | нет | Значение или массив значений. Можно передавать число или строку с суффиксом `p`, `n`, `u`, `m`, `k`, `meg`, `M`, `g`. |
| `model` | нет | Имя модели для деталей, у которых есть поле `ModelName`. |

Сервер создаёт элементы типа `Comp`. Блоки `Instrument` (измерительные
приборы) и `ExtComp` (внешние компоненты и подсхемы) читаются и проверяются,
но новые блоки этих типов пока не создаются: их состав зависит от
установленной версии EWB и не входит в библиотеку из 40 `PartNum`.

## Геометрия выводов

Смещения выводов восстановлены для 17 записей:

`0, 1, 2, 3, 4, 5, 6, 8, 9, 11, 12, 13, 15, 17, 22, 38, 39`.

Для них `ewb_list_parts` возвращает карту `rotations`: код поворота → номер
вывода → смещение `[dx, dy]` относительно `Position`. Абсолютная координата
вывода:

```text
pin_abs = (Position.x + dx, Position.y + dy)
```

Если для запрошенного компонента или поворота геометрии нет:

- компонент всё равно создаётся и читается;
- `terminal_count` может быть `null`, поэтому проверка номера вывода
  ограничена только неотрицательным значением;
- новый провод сохраняется без поля `segs` — так же, как EWB хранит провод,
  маршрут которого ещё не записан;
- сервер добавляет предупреждение: отдельное — если геометрия не наблюдалась
  для детали вообще, и отдельное — если геометрия есть, но не для выбранного
  поворота.

Точные смещения не дублируются в этой таблице: их удобнее получать через
`ewb_list_parts` с `include_rotations=true`, чтобы не рассинхронизировать
документацию и код.

## Значения и модели

Для большинства деталей `Value` состоит из нескольких полей. Если передать
скаляр, сервер запишет его в первое поле, а остальные заполнит значениями по
умолчанию. Полные массивы `value_default` и `model_units_default` возвращает
`ewb_list_parts`.

- Детали без поля `Value`: `DIODE`, `NPN_TRANSISTOR`, `PNP_TRANSISTOR`,
  `TRANSFORMER`, `OPAMP`, `ZENER_DIODE`, `LED` и все JFET/MOSFET. Передавать
  им `value` нельзя.
- Детали без поля `ModelName`: `GROUND`, `CONNECTOR`, `NODE`. Передавать им
  `model` нельзя.
- Для остальных деталей `model` необязателен; если не указан, используется
  восстановленное значение по умолчанию: `ideal` для полупроводников и пустая
  строка для деталей, у которых поле `ModelName` присутствует, но не задано.

## Особые случаи

- **Земля (`GROUND`, PartNum 8).** EWB хранит все земли с обозначением `0`.
  Несколько земель в одной схеме — нормально. При выборе земли по `ref`
  возникает неоднозначность, поэтому используйте `index`.
- **Узел (`NODE`, PartNum 39).** Это маркер соединения, а не источник.
  RefID узла — число; сервер выдаёт следующее свободное.
- **Соединитель (`CONNECTOR`, PartNum 9).** В наблюдаемых файлах имеет четыре
  вывода; не путайте его с отдельным проводом.
- **Приборы.** `AMMETER` и `VOLTMETER` входят в библиотеку `Comp`; блоки
  `Instrument` — это отдельный механизм EWB, который сервер пока только
  читает.

## Проверка результата

После добавления компонента полезно вызвать `ewb_read_schematic` и
`ewb_validate`. Они покажут `partnum`, `name`, `refid`, позицию, доступную
геометрию выводов и предупреждения. Открытие файла в самой EWB не
проверялось: приложение не устанавливалось и не запускалось, поэтому
структурная валидация не заменяет проверку в EWB.
