# Диагностика

## Сервер не запускается

### `python3: command not found`

Установите Python 3.8 или новее и убедитесь, что `python3` доступен в `PATH`:

```bash
python3 --version
```

На Windows иногда команда называется `python`, а не `python3`. В конфигурации
MCP замените `command` на `python`.

### `ModuleNotFoundError`

Сервер использует только стандартную библиотеку. Все его модули лежат в
каталоге `scripts/`: `server.py`, `ewb_codec.py`, `ewb_doc.py`, `ewb_parts.py`
и `ewb_svg.py`. Если клиент запускает `scripts/server.py` по абсолютному пути,
модули всё равно находятся рядом с файлом. Ошибка обычно означает, что
скопирован только один файл.

Проверка:

```bash
cd /path/to/ewb_mcp
python3 -c "import sys; sys.path.insert(0, 'scripts'); import server; print(server.SERVER_NAME)"
```

### MCP-клиент не видит инструменты

1. Проверьте, что сервер запускается вручную:

   ```bash
   cd /path/to/ewb_mcp
   printf '%s\n' \
     '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"check","version":"1"}}}' \
     | python3 scripts/server.py
   ```

   В ответе должно быть `"name": "ewb512-schematic"`.

2. Проверьте путь в конфигурации клиента. Для большинства клиентов нужен
   абсолютный путь к `scripts/server.py`.
3. Перезапустите клиент или перезагрузите окно.
4. Посмотрите логи MCP-сервера в клиенте.

## Ошибки пути

### `path ... is outside the allowed directories`

Сервер разрешает только:

- текущий каталог (`Path.cwd()`);
- каталог проекта (`HERE`);
- `/tmp` и `/private/tmp`;
- домашний каталог, если `EWB_MCP_ALLOW_HOME=1`;
- каталоги из `EWB_MCP_ALLOWED_DIRS`.

Решения:

```bash
export EWB_MCP_ALLOWED_DIRS="/path/to/schematics:/tmp"
```

или в конфигурации MCP:

```json
"env": {
  "EWB_MCP_ALLOWED_DIRS": "/path/to/schematics"
}
```

На Windows разделитель — `;`.

Не включайте весь домашний каталог без необходимости. Если схемы лежат в
одном каталоге, укажите именно его.

### `expected a .ewb file`

Инструменты принимают только `.ewb`. Расширение проверяется без учёта
регистра.

### `file not found`

Путь относительный — он считается от текущего каталога сервера, а не от
каталога клиента. Используйте абсолютный путь.

## Ошибки формата

### `payload marker not found`

Файл не является `.ewb` или заголовок повреждён. Проверьте первые байты:

```bash
xxd -l 160 "/path/to/file.ewb"
```

В начале должно быть `Electronics Workbench Circuit File` и строка с `/`.

### `terminator not found`

В полезной нагрузке нет символа `!`. Файл обрезан или повреждён.

### `invalid encoded pair`

Повреждена пара-кодировка. Возможные причины: файл открывали как текст,
перекодировали в UTF-8, обрезали или склеили с другим файлом.

### `stored checksum does not match the document`

Контрольная сумма в файле не соответствует документу. EWB может открыть файл,
но сервер помечает это предупреждением. Если файл создан не EWB, а другой
программой, проверьте его в самой EWB.

### `refusing to edit ... byte-for-byte`

Парсер не смог воспроизвести документ байт-в-байт. Это защита: редактирование
могло бы потерять незнакомые поля. Файл можно читать через
`ewb_read_schematic` и `ewb_validate`, но не изменять. Сообщите о таком файле,
приложив описание структуры, но не выкладывая конфиденциальные данные.

### `unterminated block`

Нарушена вложенность `{`/`}`. Файл повреждён.

## Компоненты и провода

### `unsupported PartNum ... (supported: 0..39)`

Каталог EWB 5.12 содержит PartNum 0..39. Другие номера не создаются. Посмотрите
`ewb_list_parts`.

### `unknown part '...'`

Имя не совпало с каталогом. Используйте имя из `ewb_list_parts`, например
`RESISTOR`, `CAPACITOR`, `LED`, `GROUND`, или числовой PartNum.

### `reference '0' is ambiguous`

У всех земель RefID `"0"`. Используйте `index`:

```json
{"path": "/tmp/circuit.ewb", "index": 0, "x": 410, "y": 620}
```

### `reference 'R1' is already used`

RefID должен быть уникальным, кроме земли. Укажите другой `ref` или не
передавайте его — сервер сгенерирует следующий свободный.

### `pin geometry is unknown`

Для выбранного поворота нет данных о выводах. Провод будет создан без `segs`,
и EWB сама построит маршрут. Это не ошибка. Если нужен явный маршрут,
используйте поворот из `rotations` в `ewb_list_parts`.

### `explicit route does not end at the target pin`

Сумма сегментов не приводит в координату целевого вывода. Используйте
`route: "auto"` или проверьте направление и длины.

### `wire ... duplicates another wire`

Между теми же выводами уже есть провод. Передайте
`allow_duplicate: true`, если дубликат действительно нужен.

### `component has N attached wire(s)`

Удаление компонента с проводами при `remove_wires=false` запрещено. Либо
удалите провода, либо разрешите `remove_wires: true`.

## Клиенты и плагины

### Claude Code не видит плагин

Проверьте:

```bash
claude plugin details ewb512-schematics
```

Убедитесь, что marketplace добавлен из каталога, где лежит
`.claude-plugin/marketplace.json`, а не из его родителя.

### Cursor не запускает сервер

Cursor не раскрывает `${PLUGIN_ROOT}`. В `.cursor-plugin/plugin.json`
используется `${CURSOR_PLUGIN_ROOT}`; не заменяйте его на `${PLUGIN_ROOT}`.
Если плагин всё равно не работает, добавьте `.cursor/mcp.json` с абсолютным
путём вручную (см. `docs/INSTALL.md`).

### Codex не находит marketplace

Проверьте, что путь указывает на каталог с `.agents/plugins/marketplace.json`:

```bash
ls .agents/plugins/marketplace.json
```

Синтаксис команд Codex менялся; актуальный вариант смотрите в
`codex plugin --help`.

### Muse не видит MCP-сервер

Muse не передаёт `env` в манифесте. В пакете для этого используется
`scripts/ewb_mcp_launcher.py`. Убедитесь, что установлен весь каталог, а не
только `.muse-plugin/plugin.json`.

### Devin запускает не тот сервер

В `.devin-plugin/plugin.json` MCP-сервер объявлен явно, чтобы не использовался
корневой `.mcp.json` с переменной `${CLAUDE_PLUGIN_ROOT}`. Если вы правите
манифест, сохраните inline-блок `mcpServers`.

### OpenCode: сервер не стартует

В OpenCode используется ключ `environment`, а не `env`, и массив `command`:

```json
{
  "mcp": {
    "ewb512": {
      "type": "local",
      "command": ["python3", "/absolute/path/to/ewb_mcp/scripts/server.py"],
      "environment": {"EWB_MCP_ALLOW_HOME": "1"}
    }
  }
}
```

После правки конфигурации перезапустите OpenCode.

### Плагин установлен, но skill не виден

Skills лежат в `skills/ewb-schematics/SKILL.md`. Некоторые клиенты
подхватывают их только после перезапуска сессии. Если клиент не поддерживает
skills, попросите агента прочитать файл напрямую.

### После обновления плагина работает старая версия

Клиенты кэшируют плагины. Удалите плагин и установите заново либо очистите
кэш клиента. Для локальной разработки используйте ссылку/симлинк, если клиент
это поддерживает.

## Файлы и резервные копии

### Где `.bak`

Перед каждой записью существующего файла сервер копирует его в
`<имя>.ewb.bak` рядом. `.bak` перезаписывается при следующем изменении.
Это одна резервная копия, а не история версий.

### Файл изменился, но EWB его не открывает

1. Запустите `ewb_validate` на файле.
2. Проверьте `errors`, `warnings` и `checks`.
3. Сравните с `.bak`.
4. Если `document_roundtrip_exact` был `true`, а EWB всё равно не открывает
   файл, проблема может быть в незнакомом блоке, который сервер сохранил, но
   не понял. Приложите описание структуры.

### Можно ли восстановить файл

Да, если есть `.bak`:

```bash
cp "circuit.ewb.bak" "circuit.ewb"
```

Или используйте систему контроля версий.

## Тесты

```bash
cd /path/to/ewb_mcp
python3 -m unittest discover -s tests -v
```

Тест `OriginalSchematicTests` пропускается, если нет
`local/examples/лаба 4.ewb`. Это нормально для чистого клона: пример не
поставляется.

Если тесты падают на конкретной версии Python, проверьте, что используется
Python 3.8+:

```bash
python3 -c "import sys; print(sys.version)"
```

## Безопасность

Сервер:

- не запускает EWB;
- не использует сеть;
- не устанавливает пакеты;
- читает и пишет только файлы в разрешённых каталогах;
- не следует символическим ссылкам за пределы разрешённых каталогов при
  проверке пути (`Path.resolve`);
- делает резервную копию перед изменением.

Если клиент запускает сервер с правами пользователя, сервер имеет доступ к
тем же файлам, что и пользователь, в пределах разрешённых каталогов.
Ограничивайте `EWB_MCP_ALLOWED_DIRS`, если это важно.
