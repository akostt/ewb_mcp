# EWB 5.12 MCP — чтение, редактирование и создание схем

MCP-сервер для файлов Electronics Workbench 5.x (`.ewb`). Он умеет читать
схему, показывать компоненты, выводы и связи, проверять структуру,
редактировать элементы и провода, создавать новые файлы и рендерить
SVG-превью.

Формат восстановлен исключительно реверс-инжинирингом установщика и реального
файла `local/examples/лаба 4.ewb`. Сама EWB не устанавливалась и не
запускалась. Сервер не содержит кода, ресурсов или бинарников EWB.

Пакет можно установить как плагин в Claude Code, Codex и Gemini CLI, а также
подключить к любому MCP-клиенту вручную.

## Что внутри

- `server.py` — MCP-сервер на stdlib, без внешних зависимостей.
- `ewb_codec.py` — контейнер `.ewb`: заголовок, pair-кодирование, сжатие,
  checksum.
- `ewb_doc.py` — точный разбор и запись документа `Project_5_1`.
- `ewb_blank.py` — генерация пустого документа из описания формата.
- `ewb_parts.py` — каталог компонентов, геометрия выводов, значения,
  маршрутизация проводов.
- `ewb_svg.py` — SVG-превью.
- `skills/ewb-schematics/SKILL.md` — инструкция для агента.
- `local/examples/rc_led.ewb` — локальный пример созданной схемы (не входит в
  git и в распространяемый пакет).
- `local/bin/` — локальные бинарники и база IDA (не входят в git).

`blank_template.ewb` в пакет не входит. Новые файлы собираются кодом в
`ewb_blank.py`: заголовок `CircuitHeader`, `Preferences`, пустые `Elements` и
`Wires`. Остальные необязательные блоки EWB инициализирует своими значениями
при открытии или сохранении файла.

## Требования

- Python 3.8 или новее.
- Внешние Python-пакеты не нужны.
- EWB устанавливать не требуется.

## Установка как плагин

### Claude Code

Пакет содержит plugin-манифест `.claude-plugin/plugin.json` и локальный
маркетплейс `.claude-plugin/marketplace.json`.

В терминале:

```bash
cd /path/to/ewb_mcp
claude plugin marketplace add "$PWD"
claude plugin install ewb512-schematics@ewb512-plugins
```

Или внутри сессии Claude Code:

```text
/plugin marketplace add /path/to/ewb_mcp
/plugin install ewb512-schematics@ewb512-plugins
```

После установки перезапустите сессию, чтобы Claude Code подхватил MCP-сервер и
skill. Проверить состав можно командой:

```bash
claude plugin details ewb512-schematics
```

Обновление после изменения файлов:

```bash
claude plugin marketplace update ewb512-plugins
claude plugin update ewb512-schematics
```

### Codex

Пакет содержит сразу несколько совместимых манифестов:

- `plugin.json` — Agent Plugins (`agent-plugins.org`, схема 1.0.0);
- `.codex-plugin/plugin.json` — legacy-манифест Codex;
- `mcp.json` — MCP-конфигурация для Codex;
- `.claude-plugin/marketplace.json` — маркетплейс, который Codex также
  распознаёт.

Установка:

```bash
cd /path/to/ewb_mcp
codex plugin marketplace add "$PWD"
codex plugin add ewb512-schematics@ewb512-plugins
```

Если в вашей версии Codex команда называется иначе, посмотрите
`codex plugin marketplace --help` и `codex plugin add --help`: синтаксис
подкоманд менялся между сборками.

Codex запускает сервер с рабочим каталогом плагина (`cwd: "."` в `mcp.json`),
поэтому в конфигурации выставлен `EWB_MCP_ALLOW_HOME=1`. Благодаря этому
схемы в домашнем каталоге остаются доступны.

### Gemini CLI

Пакет содержит `gemini-extension.json` и `GEMINI.md`.

```bash
cd /path/to/ewb_mcp
gemini extensions install "$PWD"
```

Для разработки можно использовать ссылку вместо копирования:

```bash
cd /path/to/ewb_mcp
gemini extensions link "$PWD"
```

Синтаксис команд расширений зависит от версии Gemini CLI; актуальный список
подкоманд показывает `gemini extensions --help`.

### Другие MCP-клиенты

Claude Desktop, Cursor, Windsurf, Cline, Continue, VS Code и другие клиенты
принимают обычный `mcpServers`. Пример лежит в `mcp_config.example.json`:

```json
{
  "mcpServers": {
    "ewb512": {
      "command": "python3",
      "args": ["/path/to/ewb_mcp/server.py"],
      "env": {
        "EWB_MCP_ALLOWED_DIRS": "/path/to/schematics:/tmp"
      }
    }
  }
}
```

Замените путь на свой. `EWB_MCP_ALLOWED_DIRS` не обязателен, если схемы лежат
в рабочем каталоге клиента, в каталоге проекта или в `/tmp`. Для доступа к
домашнему каталогу можно добавить:

```json
"EWB_MCP_ALLOW_HOME": "1"
```

### Ручной запуск

```bash
cd /path/to/ewb_mcp
python3 server.py
```

Сервер общается через stdio по JSON-RPC 2.0: построчный формат, также
поддерживается `Content-Length`. Сообщения протокола идут в stdout, служебный
лог — в stderr.

## Инструменты

| Инструмент | Назначение | Основные аргументы |
|---|---|---|
| `ewb_list_parts` | Каталог компонентов EWB: PartNum, имя, число выводов, известные повороты | `query`, `only_with_pins` |
| `ewb_read_schematic` | Прочитать компоненты, выводы, провода, сети и предупреждения | `path`, `include_pins`, `include_wires`, `include_nets`, `include_text` |
| `ewb_render_svg` | Построить SVG-превью схемы | `path`, `output_path`, `width`, `height`, `inline` |
| `ewb_create_schematic` | Создать новый `.ewb`, сразу с компонентами и проводами | `path`, `overwrite`, `description`, `components`, `wires` |
| `ewb_add_component` | Добавить компонент в существующую схему | `path`, `part`, `x`, `y`, `rotation`, `ref`, `value`, `model` |
| `ewb_add_wire` | Соединить два вывода проводом | `path`, `from`, `from_pin`, `to`, `to_pin`, `route`, `node`, `colour` |
| `ewb_update_component` | Переместить, повернуть, переименовать или изменить значение | `path`, `index` или `ref`, `x`, `y`, `rotation`, `refid`, `value`, `model` |
| `ewb_update_wire` | Изменить маршрут, метку сети, цвет или id провода | `path`, `index`, `route`, `node`, `colour`, `wire_id` |
| `ewb_remove_component` | Удалить компонент и связанные провода | `path`, `index` или `ref`, `remove_wires` |
| `ewb_remove_wire` | Удалить провод по индексу | `path`, `index` |
| `ewb_validate` | Проверить контейнер, документ, элементы, индексы, выводы, маршруты и checksum | `path` |

### Создание схемы

`ewb_create_schematic` принимает массив `components` и массив `wires`:

```json
{
  "path": "/path/to/ewb_mcp/local/examples/my_schematic.ewb",
  "overwrite": true,
  "description": "RC + LED",
  "components": [
    {"part": "GROUND", "x": 400, "y": 620},
    {"part": "GROUND", "x": 730, "y": 620},
    {"part": "BATTERY", "ref": "V1", "x": 400, "y": 500, "value": 9},
    {"part": "RESISTOR", "ref": "R1", "x": 500, "y": 460, "rotation": 1, "value": "1k"},
    {"part": "CAPACITOR", "ref": "C1", "x": 600, "y": 480, "value": "1u"},
    {"part": "LED", "ref": "D1", "x": 700, "y": 480, "rotation": 2}
  ],
  "wires": [
    {"from": "V1", "from_pin": 1, "to": "R1", "to_pin": 0},
    {"from": "R1", "from_pin": 1, "to": "C1", "to_pin": 0},
    {"from": "C1", "from_pin": 1, "to": "D1", "to_pin": 1},
    {"from": "D1", "from_pin": 0, "to": 1, "to_pin": 0},
    {"from": "V1", "from_pin": 0, "to": 0, "to_pin": 0}
  ]
}
```

В `wires` поля `from`/`to` могут быть индексом компонента в этом же вызове или
его `ref`. Если `ref` не задан, сервер генерирует обозначение. Значения можно
передавать числом или строкой с суффиксом `k`, `M`, `u`, `n`, `p`
(например, `"1k"` или `"1u"`).

Готовый пример: `local/examples/rc_led.ewb` и его превью
`local/examples/rc_led.svg`. Каталог `local/` не попадает в git и в
распространяемый пакет; при необходимости пример можно создать заново любым
вызовом `ewb_create_schematic`.

### Чтение и проверка

```json
{"path": "local/examples/лаба 4.ewb", "include_nets": true}
```

`ewb_read_schematic` возвращает:

- `elements` — индекс, `PartNum`, имя, `refid`, позицию, поворот, значение,
  модель и абсолютные координаты выводов;
- `wires` — индексы элементов на концах, номера выводов, метку сети, цвет,
  сегменты маршрута;
- `nets` — электрические узлы, построенные по проводам;
- `warnings` — структурные замечания (не ошибки).

`ewb_validate` возвращает `valid`, `errors`, `warnings`, `checks` и `details`.
Ошибки означают, что файл нельзя безопасно редактировать или он повреждён.
Предупреждения не блокируют работу.

### Редактирование

Все изменяющие инструменты работают с существующим файлом и сохраняют его в
формате EWB 5.12. Запись атомарная, предыдущая версия сохраняется рядом как
`<имя>.ewb.bak`.

Порядок типичной правки:

1. `ewb_read_schematic` или `ewb_validate` — посмотреть индексы и выводы.
2. `ewb_update_component` / `ewb_add_component` — изменить состав.
3. `ewb_add_wire` / `ewb_update_wire` — соединить или переразвести.
4. `ewb_validate` — проверить результат.
5. `ewb_render_svg` — посмотреть превью.

Если компонент двигают или поворачивают, провода, подключённые к его выводам,
переразводятся автоматически, когда геометрия выводов известна. Для неизвестной
геометрии сервер оставляет провод без сегментов и выдаёт предупреждение: EWB
сама проложит его при открытии.

Важно: у всех земляных символов `refid` равен `"0"`. Поэтому для земли
используйте индекс элемента, а не `ref`. Строка `"2"` в `ref` означает
обозначение `2`, а не индекс; индекс передавайте числом.

## Поддерживаемый формат

### Контейнер

- Заголовок — обычный текст с CRLF, заканчивается строкой `/`.
- Поддерживается `EncryptionType: 2` (формат EWB 5.x).
- Полезная нагрузка — пары байтов, блоки со сжатием в стиле PKWARE implode.
- Контрольная сумма — CRC32 от документа, хранится в заголовке.
- Документ внутри контейнера — текст `Project_5_1`.

Пересжатие контейнера не обязано совпадать с исходным файлом побайтно: EWB
допускает разные корректные варианты сжатия. Поэтому `checks` может показывать
`container_roundtrip_exact: false`, но документ при этом читается и checksum
совпадает. Для редактирования важнее `document_roundtrip_exact: true` — если
парсер не воспроизводит документ байт-в-байт, сервер отказывается писать файл.

### Документ

Дерево блоков `Block`/`Document`:

- `Project_5_1`
  - `Circuit`
    - `Elements` — `Comp`, `Instrument`, `ExtComp`
    - `Wires` — провода
  - `Common` — общие поля, например `RefID`

У компонента есть `PartNum`, `Position` (`rotation x y`), `Value`, `ModelUnits`,
`ModelName`, `Status` и общие поля. У провода — `pos` с индексами элементов и
номерами выводов, необязательные `segs`, `colour`, `wire_id`, `node_p`,
`x_factor`, `y_factor`.

Индексы в `pos` — это позиции элементов в общем упорядоченном списке
`Elements`, а не `refid`. Поэтому после добавления или удаления компонента
индексы проводов соответствующим образом обновляются сервером.

Пустой документ для нового файла генерируется в `ewb_blank.py`. В нём есть
только `CircuitHeader` (версия внутренней схемы, масштаб, версия, библиотека
`"$"`, параметры печати), `Preferences`, пустые `Elements` и `Wires`.
`InstSettings`, `WindowInfo`, `AnalysisValues`, `GrapherInfo`,
`SimulationOptions` и другие необязательные блоки не создаются: загрузчик EWB
инициализирует их значения по умолчанию перед разбором файла и записывает при
сохранении. Это позволяет не поставлять файл-шаблон, созданный приложением.

### Координаты и выводы

`Position` — это опорная точка элемента, а не центр корпуса. Абсолютная
координата вывода:

```text
pin_abs = Position + pin_offset(PartNum, rotation, pin)
```

Смещения выводов намеренно несимметричны (например, у резистора при
`rotation: 0` выводы могут быть в `(-20, -10)` и `(40, -10)`). Поэтому для
проводов используются реальные координаты выводов, а не геометрический центр.

Поворот задаётся числом `0..7`. Не для всех типов и поворотов геометрия была
наблюдена в реальных файлах; `ewb_list_parts` показывает известные повороты.
Если геометрия неизвестна, компонент всё равно можно создать, но автоматическая
маршрутизация провода может быть недоступна.

### Провода и направления

Сегменты провода хранятся парами `[direction, length]`. Коды направлений:

| Код | Направление |
|---:|---|
| 1 | +X (вправо) |
| 2 | +Y (вниз) |
| 4 | −X (влево) |
| 8 | −Y (вверх) |
| 3, 6, 9, 12 | диагонали |

`route: "auto"` строит ортогональный маршрут, `route: "none"` оставляет провод
без `segs`, чтобы EWB проложила его сама. Можно передать и явный список пар.

### Земля

EWB использует обозначение `0` для всех земляных символов. Поэтому в схеме
может быть несколько элементов с `refid: "0"`; это нормально. Если нужно
обратиться к конкретной земле, используйте её индекс в `elements`, а не `ref`.

## Политика путей и безопасность

По умолчанию разрешены:

- текущий рабочий каталог;
- каталог проекта (родитель `ewb_mcp`);
- `/tmp` и `/private/tmp`;
- каталоги из `EWB_MCP_ALLOWED_DIRS` (через `:` на macOS/Linux).

Дополнительно:

- `EWB_MCP_ALLOW_HOME=1` добавляет домашний каталог. Этот флаг включён в
  плагинных конфигурациях, потому что плагин может запускаться со своим
  рабочим каталогом и иначе не увидит схемы пользователя.
- Уберите флаг, если нужна более строгая изоляция, и задайте явный
  `EWB_MCP_ALLOWED_DIRS`.

Пути вне этого списка отклоняются. Расширение должно быть `.ewb` для схем и
`.svg` для превью.

Сервер не устанавливает и не запускает EWB. Он также не перезаписывает
исходный файл, если вы сами не передали его путь в изменяющий инструмент.
Запись атомарная, резервная копия `.bak` создаётся перед изменением.

## Проверка

На реальном файле `local/examples/лаба 4.ewb`:

- прочитано 97 элементов, 98 проводов, 98 сетей;
- `ewb_validate`: `valid: true`, 0 ошибок, 0 предупреждений;
- `document_roundtrip_exact: true`, `checksum_matches: true`;
- добавление, перемещение и удаление компонента и провода проходят без ошибок;
- исходный файл не изменялся (SHA-256 до и после совпадает);
- резервная копия `.bak` создаётся.

Пример `local/examples/rc_led.ewb`:

- 6 элементов, 5 проводов, 5 сетей;
- `valid: true`, 0 ошибок, 0 предупреждений;
- все три проверки `checks` — `true`.

Новый файл, созданный без шаблона (`ewb_create_schematic`):

- 4 элемента, 4 провода, 3 сети;
- `valid: true`, 0 ошибок, 0 предупреждений;
- `document_roundtrip_exact: true`, `container_roundtrip_exact: true`,
  `checksum_matches: true`;
- размер контейнера — около 1.8 КБ.

Плагин Claude Code проверен локально: `claude plugin validate --strict`
проходит, установка из локального маркетплейса создаёт skill и MCP-сервер,
сервер запускается из кэша плагина.

## Разработка и тесты

Из корня репозитория:

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют побайтовый round-trip пустого документа и контейнера, сжатие
и распаковку блоков, создание, чтение и правку схемы, резервные копии,
политику путей и SVG-превью. Исходная схема из `local/examples/` проверяется
дополнительно, если она есть; в чистом клоне этот тест пропускается.

CI в `.github/workflows/tests.yml` запускает тот же набор на Python 3.8,
3.10, 3.12 и 3.13. Правила участия — в `CONTRIBUTING.md`, история версий — в
`CHANGELOG.md`.

## Ограничения

- Поддерживается только `EncryptionType: 2`. Старые файлы с другим типом
  контейнера отклоняются с понятной ошибкой.
- Нет симуляции, расчёта цепей и электрического ERC: проверяется структура
  файла, индексы, выводы, маршруты и checksum.
- SVG — приблизительное превью, а не точная копия отрисовки EWB. В плотных
  схемах подписи могут пересекаться; для читаемости они рисуются с белой
  обводкой.
- Значения многих компонентов состоят из нескольких полей. В превью
  показывается только первое (основное) значение; остальные поля сохраняются.
- Для части экзотических компонентов и поворотов геометрия выводов не была
  наблюдена. Такие элементы можно читать и создавать, но автоматическая
  переразводка проводов для них ограничена.
- Проверка открытия файла в самой EWB не выполнялась: по условию задачи
  приложение не устанавливалось и не запускалось. Формат и поведение загрузчика
  восстановлены по дизассемблеру и реальным файлам.

## Совместимость и лицензирование

Код написан с нуля по результатам реверс-инжиниринга формата. В
распространяемом пакете (git и plugin-кэш) нет исполняемых файлов EWB, её
библиотек, ресурсов, шрифтов или извлечённого шаблона схемы. Пустой документ
генерируется программно из описания полей. Локальный установщик и база IDA
лежат только в игнорируемом каталоге `local/bin/` и не входят в пакет.
Текстовые имена блоков и полей (`Project_5_1`, `Circuit`, `Elements`, `Wires`,
`Comp`, `wire`, `PartNum`, `Position` и т. п.) необходимы для совместимости
формата и не являются копированием реализации.

Лицензия пакета — MIT, см. `LICENSE`.

`ewb_mcp` инициализирован как отдельный git-репозиторий. Папка `local/`
добавлена в `.gitignore` целиком: её содержимое не попадает в коммиты, но
остаётся на диске и доступно MCP-серверу для чтения и правки схем.

Каталог `ewb_mcp` можно переносить целиком в любое место. Плагинные
конфигурации вычисляют путь к `server.py` от корня плагина, а примеры и
бинарники лежат в `local/` внутри каталога, поэтому после переноса ничего
дополнительно настраивать не нужно.
